# 运行手册

本手册面向负责 NovaLink 日常值守、频道运营和故障处置的管理员。它强调先观察、再变更、最后验证：后端控制台和管理 API 都可以改变玩家、频道、客户端或配置状态，因此不应把高影响命令当作普通排障工具。[1] [2]

> **使用原则。** 在生产环境执行任何治理、重载、断连或公告操作前，先记录时间、操作者、目标、原因和预期回退方式。若当前影响范围不清楚，优先使用只读命令获取事实，而不是先执行修复动作。

## 1. 运行观察

后端本地控制台提供 `status`、`players`、`clients`、`channels`、`channel`、`mutes`、`bans` 和 `spies` 等观察命令。执行 `help` 或 `?` 可查看当前版本支持的命令摘要与参数提示。[1]

| 目标 | 首选动作 | 应确认的信号 |
| --- | --- | --- |
| 判断后端是否存活 | `status` | 进程正常、服务无致命错误、运行时统计合理。 |
| 查看接入端状态 | `clients` | 已认证客户端数量、平台、连接时间与异常断开。 |
| 查看玩家状态 | `players` | 玩家 UUID、来源客户端、频道与治理状态。 |
| 查看频道 | `channels` 或 `channel <id>` | 频道 ID、范围、成员、容量与归属客户端。 |
| 查看治理状态 | `mutes`、`bans` | 目标、范围、期限和原因是否符合预期。 |
| 查看监听会话 | `spies` | 监听状态是否必要且符合权限要求。 |

管理面板也可通过 REST/WS 展示相同类别的运行时快照。面对数据不一致时，应优先信任当前后端日志和本地控制台，再检查面板连接、token 和代理路径。[2] [3]

## 2. 常见操作流程

### 2.1 接入端离线或频繁重连

| 阶段 | 动作 | 通过条件 |
| --- | --- | --- |
| 观察 | 使用 `clients` 确认哪个 `clientId` 离线或不稳定 | 识别具体接入端，而不是只看总数。 |
| 定位 | 检查后端认证/网络日志和接入端日志 | 区分凭据、协议、允许 IP、端口、网络或平台生命周期问题。 |
| 处置 | 修复根因后让接入端受控重连或重启 | 不反复断连仍未定位的问题。 |
| 验证 | 重新检查 `clients`、频道同步和测试消息 | 客户端已认证、频道与消息范围正确。 |
| 记录 | 写入故障时间线与根因 | 为后续优化提供证据。 |

接入端对非预期断线采用有上限的指数退避；显式停用不应触发自动重连。若看到持续失败，重点检查后端配置中的客户端身份、允许 IP 和协议版本，而不是单纯增加重试次数。[4]

### 2.2 安全地重载配置

后端支持文件监听和显式 `reload`。配置重载会更新配置化频道和已实现的功能开关，并可向已连接客户端广播脱敏的频道/模板同步数据。[5]

| 阶段 | 动作 | 验证 |
| --- | --- | --- |
| 变更前 | 备份当前 `novalink.yml`，保存差异与预期影响 | 可恢复原配置。 |
| 审阅 | 检查 YAML、频道作用域、权限、允许 IP 与功能开关 | 不把未解析的参考段误当成生效配置。 |
| 执行 | 在控制台运行 `reload` 或调用 `POST /api/reload` | 日志显示重载成功。 |
| 验证 | 运行 `channels`、`clients` 并进行受控消息测试 | 频道与接入端状态符合预期。 |
| 回退 | 异常时恢复上一份配置并再次重载/按流程重启 | 影响范围得到收敛。 |

不要把端口、反向代理、数据库切换、JAR 升级或密钥轮换当作普通热重载场景；它们需要独立的部署和回退流程。[6]

### 2.3 频道与成员治理

频道治理操作包括查看、创建、删除及通过平台/管理控制面调整成员。删除频道之前，后端会先处理成员移除；因此请先确认该频道是否承载运营公告、世界聊天或私有协作会话。[2]

| 场景 | 建议动作 | 额外检查 |
| --- | --- | --- |
| 新建临时运营频道 | 先确定作用域、容量、权限和命名，再创建 | 防止把局部频道误建为全局范围。 |
| 关闭频道 | 先通知成员、导出必要记录，再删除 | 确认没有自动化或面板订阅依赖它。 |
| 玩家被错误加入频道 | 检查玩家 UUID 与频道成员列表，再移除 | 复核玩家状态是否同步更新。 |
| 世界频道路由错误 | 查看 `allowed_worlds` 与客户端世界上报 | 在目标平台实测，不只检查 YAML。 |

### 2.4 禁言、封禁与踢出

后端控制台支持 `mute`、`unmute`、`ban`、`unban` 与 `kick`，管理 API 也提供对应路由。无论入口如何，管理员都应明确目标 UUID、频道范围、持续时间和原因。[1] [2]

| 操作 | 影响 | 执行前必须确认 | 执行后验证 |
| --- | --- | --- | --- |
| 禁言 | 限制玩家发送消息 | 玩家 UUID、全局/频道范围、持续时间、理由 | `mutes`、目标频道消息行为、通知。 |
| 解除禁言 | 恢复发送权限 | 是否为正确玩家和正确频道范围 | 治理记录与实际消息行为。 |
| 封禁 | 限制玩家参与相关聊天/频道路径 | 影响范围、期限、证据与申诉渠道 | `bans`、重新接入/路由行为。 |
| 解除封禁 | 恢复限制 | 原封禁记录和审批 | 状态与访问范围。 |
| 踢出频道 | 仅移出指定频道成员关系 | UUID、必需的 `channelId`、业务影响 | 成员列表和玩家频道状态。 |

不要用“尝试一下”替代治理判断。对高争议或跨服务器影响操作，建立双人复核或审批记录会更安全。

### 2.5 公告、标题与监听

控制台支持 `announce`、`title`、`spy` 和 `spies`。这些能力影响多个玩家的可见内容或管理者可见性，应遵循最小必要原则。[1]

| 操作 | 建议用途 | 风险控制 |
| --- | --- | --- |
| 公告 | 经批准的维护、规则或运营消息 | 先确认目标频道与文案；在测试频道验证格式。 |
| 标题 | 对支持的平台发送显著提示 | 控制频率与内容，避免打扰或跨平台不一致。 |
| 监听 | 依法规、社区规则和内部权限观察必要消息 | 限制操作者、记录原因、及时关闭。 |

### 2.6 断开游戏服务器客户端

`DELETE /api/clients/{clientId}` 会关闭对应的游戏服务器 TCP 客户端连接，但不影响 WebSocket 面板会话。该操作适合在计划维护或清理异常会话时使用；执行前先检查该接入端是否承载关键频道，并确认其重连行为不会造成无效循环。[2]

### 2.7 远程控制台

`POST /api/console` 可执行受允许的后端控制台命令。为避免远程 API 直接终止后端，`stop` 与 `shutdown` 在此接口中被显式黑名单拒绝。只有本地受控控制台或进程管理系统应承担停机/重启职责。[2]

## 3. 事件响应路径

| 现象 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 所有客户端同时离线 | 检查后端进程、TCP 监听、数据库和网络边界 | 先逐台重启接入端。 |
| 单一客户端认证失败 | 对照该客户端身份、密码、允许 IP 与协议日志 | 修改全局密钥或扩大 IP 段。 |
| 跨服聊天异常 | 检查频道作用域、客户端权限、功能开关与路由日志 | 立刻删除频道或关闭全部跨服聊天。 |
| 管理面板无法加载数据 | 检查 HTTPS、反向代理、`/api`、`/ws`、token 与浏览器控制台 | 把管理端口直接暴露到公网。 |
| 配置重载失败 | 恢复已知可用配置，读取错误定位 YAML/依赖问题 | 继续对同一坏文件重复重载。 |
| 怀疑凭据泄露 | 限制访问、保留证据、轮换密钥/密码、审阅日志 | 在公共渠道粘贴完整配置排障。 |

## 4. 交接与记录模板

每次影响用户的操作至少记录以下内容：

| 字段 | 示例 |
| --- | --- |
| 时间与环境 | `2026-08-12 21:00 CST / production` |
| 操作者与审批 | `ops-a / approved by lead-b` |
| 目标 | `clientId=survival`、`channelId=global` 或玩家 UUID。 |
| 动作 | `reload`、禁言、断开客户端、变更功能开关。 |
| 原因 | 变更单、故障单或运营事件编号。 |
| 验证 | `clients`、`channels`、受控消息、面板/WS 状态。 |
| 回退 | 配置备份路径、旧版本、解除治理操作或代理回切。 |
