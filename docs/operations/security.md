# 安全基线

NovaLink 同时处理平台接入身份、管理员身份、JWT、频道与运营操作，因此安全配置必须覆盖**数据面**与**控制面**。数据面是 NovaChat 接入端到 NovaLink 的 NovaProtocol TCP 连接；控制面是管理网关提供的登录、REST 和 WebSocket 服务。两者均不应默认向不可信网络开放。[1] [2]

> **安全目标。** 让未授权来源无法建立有效连接、让管理员操作可被限制与审计、让凭据泄露后能够轮换与恢复。任何单一配置项都不能单独满足这些目标。

## 1. 优先级矩阵

| 风险 | 必须采取的控制 | 验证方式 |
| --- | --- | --- |
| 管理网关暴露到公网 | 仅通过受控反向代理、VPN 或受限网络访问；启用 HTTPS/WSS | 从非授权网络确认连接被拒，从授权路径完成登录与 WS 鉴权。 |
| 服务器端凭据泄露 | 使用随机密钥、受控文件权限、密钥轮换和日志脱敏 | 检查配置、CI、Issue、日志与 Wiki 中不存在真实凭据。 |
| 未知平台接入 | 配置 `allowed-ips` 并在网络层设置 ACL | 仅已知出口 IP 能到达 TCP 端口。 |
| JWT 被误用 | 只以 access token 访问 API/WS，不接受 refresh token | 验证 refresh token 被 REST 与 WS 拒绝。 |
| 过度授权 | 将客户端权限和管理员账户最小化 | 以不同角色验证频道和管理操作的实际边界。 |
| 变更造成误分发 | 受控时间窗口内重载，检查频道/客户端同步 | 记录配置哈希、重载日志与消息范围测试。 |

## 2. 凭据与配置文件

`novalink.yml` 包含服务签名密钥、数据库账号、客户端凭据和管理员密码哈希。应将它视为机密配置，而非普通项目文件。后端用 `server.secret-key` 构造 JWT 服务；客户端与管理员注册逻辑使用配置中的凭据数据。[1]

| 项目 | 规则 | 不应做的事 |
| --- | --- | --- |
| `server.secret-key` | 为每个环境生成独立、长且随机的值；建立轮换记录 | 使用示例值、项目名、短口令或跨环境复用。 |
| `clients[].password` | 通过受控渠道分发给对应接入端；只授予所需客户端 | 把明文放入公开仓库、截图、Issue 或聊天记录。 |
| 数据库用户名/密码 | 使用最小权限账号；限制数据库网络来源 | 使用 root/超级用户作为长期应用账号。 |
| `super-admins` | 仅保留必要管理员；变更时记录审批和验证 | 共享账号或不清理离职/不再负责的管理员。 |
| 配置文件权限 | 仅后端运行用户和受控运维用户可读 | 让 Web 服务用户、构建用户或所有本地账户可读。 |

后端对客户端密码兼容明文与 SHA-256 十六进制输入，并在客户端认证注册时归一为哈希；这是一项协议兼容行为，不代表明文凭据适合以不受控方式长期存储或传输。[1]

## 3. 网络分段与最小暴露

后端配置中的 `security.allowed-ips` 能限制尝试接入的来源。它应与防火墙、安全组、主机路由和反向代理策略共同工作，而不是取代这些网络控制。[2]

```text
已批准的 Minecraft 服务端 / 代理
           │
           ├── 仅允许到达 NovaProtocol TCP 端口
           ▼
      NovaLink 后端
           ▲
           └── 仅反向代理或 VPN 管理网段可达管理网关
                         ▲
                         └── 管理员浏览器与自动化
```

| 接口 | 建议访问者 | 应限制的来源 |
| --- | --- | --- |
| NovaProtocol TCP | 已登记的 NovaChat 接入端 | 公共互联网、未知宿主机、非授权容器。 |
| `/api/auth/*` | 受控管理员 | 任意公开来源、未加密 HTTP、无速率限制的暴力尝试来源。 |
| 其他 `/api/*` | 已认证的控制面用户或自动化 | 没有 Bearer access token 的请求。 |
| `/ws` | 已认证的控制面会话 | 未认证会话、refresh token、非受控前端来源。 |

## 4. 管理网关与令牌

HTTP 认证处理器提供 `POST /api/auth/login` 与 `POST /api/auth/refresh`；其他 REST 路由要求 `Authorization: Bearer <access-token>`。后端会显式拒绝把 refresh token 当成 API Bearer token 使用。WebSocket 在 `/ws` 升级后也要求先发送 `auth` 消息，且同样拒绝 refresh token。[3] [4]

这意味着部署层至少应做到：

1. 使用 HTTPS/WSS，避免令牌在不可信链路上明文暴露。
2. 不在前端构建产物、静态配置或 URL 查询参数中固化管理员密码和 token。
3. 为管理域名设置适合组织的访问控制、会话管理和日志审计。
4. 在怀疑 `secret-key` 或 token 泄露时，执行密钥轮换、重新认证和受影响会话审查。
5. 对自动化调用使用最小权限账户，并隔离其网络位置与凭据存储。

## 5. 配置同步与数据最小化

配置重载后的 `ConfigSyncPacket` 只序列化全局频道、模板以及客户端的用户名、显示名和频道信息；客户端密码不应被同步。将此行为视为最低限度的数据暴露，而不是向接入端复制整个后端配置的机制。[5]

管理员仍应避免在频道显示名、注释、公告、Webhook 定义或错误消息中写入敏感信息。任何进入控制面、日志或通知的文本都可能被更大范围的运维角色看到。

## 6. 运维操作的风险控制

| 操作 | 主要风险 | 建议控制 |
| --- | --- | --- |
| 重载配置 | 权限或消息范围意外变化 | 先审阅差异；在低风险时段执行；保留回退文件。 |
| 禁言、封禁、踢出 | 误操作与越权 | 核对 UUID、频道范围、持续时间和原因；记录操作上下文。 |
| 控制台命令 | 高影响或停机 | 限制控制台访问；REST 控制台不能执行 `stop`/`shutdown`，但本地控制台可。 |
| Webhook/API 集成 | 外部系统泄露与副作用 | 不把外部 URL/密钥写入公开文档；验证目标系统与失败处理。 |
| 排障日志 | 将凭据、IP 或玩家数据扩散 | 使用权限受控日志存储，并在分享前脱敏。 |

## 7. 部署前核对清单

| 检查项 | 完成标准 |
| --- | --- |
| 服务密钥 | 非示例值、独立随机、已记录轮换责任人。 |
| 网络规则 | TCP 仅接入端可达；管理网关仅反向代理/VPN/管理网段可达。 |
| TLS | 管理员浏览器使用 HTTPS/WSS；代理正确保留认证与升级头。 |
| 数据库 | 专用最小权限账号、备份、恢复演练与网络限制已完成。 |
| 管理员 | 账户列表经审阅；不再需要的超级管理员已移除。 |
| 日志与监控 | 运行日志有受控留存、轮换和异常告警路径。 |
| 变更回退 | 已保存旧 JAR、旧配置、可恢复数据备份和验证记录。 |

安全控制必须在每次新增平台、修改代理、切换数据库、增加管理员或开放自动化入口时重新审阅。部署层的完整操作见[部署指南](../guide/deployment.md)，管理行为见[运行手册](operations-runbook.md)。
